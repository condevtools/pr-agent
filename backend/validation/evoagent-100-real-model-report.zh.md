2026-10-29，使用当前 `.env` 指定的模型完成全部 100 条样本的单次测试。结论是：**新配置可调用，核心多 Agent 流程可运行，但当前执行完成率为 75%，且原数据标签有明显遗漏，尚不能据此验收真实 PR 质量。**

这批数据适合定位工程问题、建立回归基线；在补全标签前，下面的精确率、误报和命中数据只能解释为“与原始目标标签的位置一致性”。没有删除失败样例、重跑挑选结果、修改标签或启用发布。

## 冻结原标签下的结果

| 指标 | 全部 100 条 | validation 80 条 | holdout 20 条 |
| --- | ---: | ---: | ---: |
| 完整执行 | 75/100，75% | 58/80，72.5% | 17/20，85% |
| 目标位置命中 | 31/40，77.5% | 25/32，78.1% | 6/8，75% |
| 位置匹配 TP / FP / FN | 31 / 69 / 9 | 25 / 49 / 7 | 6 / 20 / 2 |
| 原标签位置精确率 | 31% | 33.8% | 23.1% |
| 原标签位置 F1 | 44.3% | 47.2% | 35.3% |
| 完整且无多余发现的样例 | 23/100 | 21/80 | 2/20 |
| 空标签样例完整且无发现 | 16/60 | 15/48 | 1/12 |

匹配规则是“一对一、同文件、预测范围覆盖标注起始行”，不是规则/CWE 语义匹配。未完成的样例一律不能获得 TP 或 clean hit；其目标标签计 FN，返回的发现计 FP。这样保留了全部 100 条的分母，但也意味着未完成样例中的有效候选仍会受到执行失败惩罚。模型返回的多余发现并不自动等于错误，见下文标签审计。

critical/high 目标的位置召回为 13/19，68.4%。31 个位置匹配中有 18 个严重级别符合标签映射，58.1%；由于产品严重级别最高为 high，评分预先将 critical 映射为 high。

## 数据集本身的限制

这 100 条的来源声明为 `synthetic-controlled`，没有真实 PR 链接、独立人工完整标注或开发集。每条正例最多只有一个目标标签，因此其他有效问题也会被原始评分计为 FP。

对全部 60 个空标签完整文件快照进行静态检查：13 条使用 `hashlib` 但未导入，11 条使用 `os` 但未导入；另有 11 条引用未定义的 `cursor`、11 条引用未定义的 `response`。共 46 条存在未解析名称。后两类若依赖外部注入变量，数据没有提供这项执行契约；按当前完整文件输入解释，至少 24 条标准库缺少导入的样例明确不应视为无缺陷。

例如，`pr-0005` 的新增行调用 `hashlib.md5(...)`，而文件仅包含 `process` 函数；`pr-0027` 新增 `os.environ[...]`，同样没有导入 `os`。模型指出这些问题会被原标签计为误报。不能把 69 个原标签 FP 或 28/60 的空标签返回发现率解释为模型幻觉率。

位置匹配也可能高估目标检出。独立复核全部 31 个匹配对，发现 6 个匹配对讨论的是另一种问题：`pr-0044`、`pr-0054`、`pr-0064`、`pr-0074`、`pr-0083`、`pr-0094`。其中 `pr-0064`、`pr-0083`、`pr-0094` 还有其他已接受发现涉及正确目标，评分器只是优先配对到另一条发现；因此不能直接将 6 个全部扣为目标漏检。

至少 `pr-0044`（浮点金额精度→转换异常）、`pr-0054`（无时区 datetime→缺少导入）、`pr-0074`（非原子文件写入→类型错误/截断）这 3 条，原始位置匹配不足以认定目标被检出。此项是独立 Agent 对合成输入的审查，不是人工标注后的新分数。严重级别匹配率同样受候选配对顺序影响。

本轮保留冻结标签与原始分数，没有在看到答案后修订标签或筛选有利子集。后续应将补全标签、补足文件上下文的数据作为**新版本**，另跑回归；这批已查看的样例可作为开发回归集，不应宣称为新的独立盲测集。

## 当前流程暴露的问题

1. **证据脱敏与截断共用状态。** 共有 21 个 gate 判定为 `evidence_location_invalid`。读取工具遇到 `[REDACTED]` 会标记为 truncated，而 gate 拒绝 truncated 记录。通过无模型调用的精确重建，已确认 `pr-0012`、`pr-0027`、`pr-0030` 的 4 个判定与该机制有关；其中 `os.environ[...]` 还会被凭据正则过度脱敏。其余判定缺少持久化工具证据元数据，不能全部归因于此。应分离脱敏与真实截断，并提供不含秘密值的结构化证据，不能简单放宽 gate。
2. **工具预算没有为最终结论保留轮次。** 13 条角色覆盖记录以 `tool_call_limit_reached` 结束。角色最后一轮仍可以请求工具；两次额度用尽后返回 partial，没有完成综合判断。应显式传递剩余额度，并让最后可用轮次只允许输出最终结果。
3. **网关报告用量超过本地估算。** 所有 521 个有 usage 的成功请求都超出本地输入估算；报告输入量/估算比值中位数 1.246，P95 为 2.211。本轮记录了 usage，但没有证明持久化预算预留准确。需要校准计量及模型定价，不能把本地估算当作可靠费用上界。
4. **仍有真实调用失败。** 共 525 次请求，521 次成功、4 次失败；其中 `pr-0026` 的三次请求返回 HTTP 401，`pr-0058` 的一次失败没有可用 HTTP 状态。日志不足以进一步确定后一项原因，且本轮没有重试隐藏失败。

全部候选 gate 判定：接受 100、critic 拒绝 98、critic 要求更多证据 5、证据位置不合法 21。这里的计数单位是候选判定，不是样例；25 条未完成样例可能同时涉及多种原因。
